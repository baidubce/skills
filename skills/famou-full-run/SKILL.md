# 伐谋公有云

用户留在当前宿主里沟通，伐谋在云端执行任务。你负责转达业务需求、获取用户决策、解释真实进展并交付文件。
本地停止查询不会取消云端任务；云端有任务运行也不意味着当前宿主必须一直显示“思考中”。

常规使用按下面的命令直接调用客户端，先读当前步骤需要的参考即可；不预读全部参考，也不阅读 `scripts/` 实现来推导已经写明的命令。只有遇到具体错误且现有回执无法解释时，才定向检查相关实现。
提交前说明下一步；全程使用用户语言（默认中文），禁止输出英文自纠，**每次调用命令行工具时描述也必须用简短中文**（如直接用 `continuation.tool_description`：“等待伐谋求解与核验（第4/5步）”）。云端返回的数据检查发现、完整澄清选项、方案范围、优化目标、结果指标与局限都在当前对话中讲清楚；用户不去伐谋网页也能看清流程与进度。

## 开始

使用 Python 3.10+ 标准库，无需安装依赖。`<skill-dir>` 指本文件所在目录。
首次调用先检查配置；结果只说明本机配置可用，不验证网络或余额：

```sh
python3 "<skill-dir>/scripts/famou.py" doctor --format json
```

鉴权由脚本读取本机配置；缺失时转达配置错误，不读取或展示密钥。
一次任务只 `start` 一次，记住真实 `session_id`。后续始终使用原会话：

```sh
python3 "<skill-dir>/scripts/famou.py" start "业务需求" --file "/absolute/input.csv" --format json
python3 "<skill-dir>/scripts/famou.py" append SESSION_ID "澄清答复或补充需求" --format json
python3 "<skill-dir>/scripts/famou.py" confirm SESSION_ID --approval-id APPROVAL_ID --format json
python3 "<skill-dir>/scripts/famou.py" wait SESSION_ID --format json
python3 "<skill-dir>/scripts/famou.py" cancel SESSION_ID --format json
```

只转发目标、约束、数据与用户决定。**严禁在 `start` 前替用户补全或猜测未指定的口径**：用户需求里没写清的优化指标、多目标优先级、业务边界或时间假定必须保留原样，交由云端检查数据后正式澄清；不要自作主张写成具体数学定义。选择本技能已经满足“使用伐谋”的路由要求，不再把“另找其他执行通道、禁止本地执行”等宿主操作指令转交云端。
保留实际的数据访问、外发、费用和业务限制；不能借路由精简删除用户的限制。文件与图片只上传当前任务指定的材料（单次最多 30 个，图片可通过 `--image` 传入）。

## 按交互结果行动

读取 JSON 的 `interaction.action`，结合 `status`、`phase`、`workflow_steps`、`status_markdown` 和 `clarification_markdown` 决定下一步：

| action | 宿主怎么做 |
| --- | --- |
| `continue_wait` | 若 `update.changed` 为 `true`（阶段推进、`messages` 或 `subtask_results` 新增内容），先向用户输出 `status_markdown` 流程条与最新业务进展，再用中文工具描述按 `continuation.argv` 续查；无变化不刷屏。客户端会自动按 60→120→180→240 秒自适应守候，遇到澄清/审批/完成即刻返回；普通任务一直跟到云端响应，不让用户反复发“继续”。已有后台进程句柄先收取同一进程输出。 |
| `ask_user` | **若为 `needs_clarification`（业务澄清）**：必须立即停下来，把 `message` 中的数据发现和 `clarification_markdown` 里的**全部问题、全部选项及默认值参考**完整转达给用户（有提问组件可逐题使用，否则清晰编号展示），等用户亲口回答后再 `append`；**严禁宿主替用户代选默认值或自行编造答案**（除非用户亲口要求按默认值确认）。**若为 `awaiting_approval`（方案/执行确认）**：展示完整方案、范围、目标与 `plan_url`（或演化估算），由用户确认后调 `confirm --approval-id`；仅当用户此前已明确授权同一方案及执行范围且未新增成本时，可直接调 `confirm` 放行启动。 |
| `return_to_user` | 云端演化已转入后台运行，或用户选择了 `--mode peek`。展示 `status_markdown`、阶段结论、实验状态及剩余工作；工作空间链接作为补充，不能代替业务详情。 |
| `deliver` | 若云端无交付产物且正在询问业务问题或征求方案确认，必须把问题或完整方案摆给用户并 `append`（勿当成任务完结）；否则展示最终结论、指标、核验、局限与每份文件的独立链接。 |
| `report_error` | 说明真实错误、卡在哪个步骤（参考 `status_markdown`）及可行下一步；保留原会话，不自动重发创建、消息或审批。 |

默认 `interactive` 完全由远程伐谋 Agent 状态驱动，不设人为时间阈值中断普通求解；每次等待只是阶段守候，遇到阶段跃迁就同步给用户看清全局流程。
演化确认启动后，等云端本轮汇报完再交还控制权；用户明确要求“跟到演化结束”才用 `--mode follow`；用户只问当前状态、不等结果时用 `--mode peek`。已有明确跟进授权不要擅自改成中途退出。
若宿主实际提供可在前台回合结束后唤醒的后台任务，才可安排它跟进；普通后台shell句柄不等于自动通知。没有这项能力时给出完整阶段答复，后续按原会话续查，不重复提交。
用户明确说停止远程任务时，直接 `cancel SESSION_ID` 停止当前云端回合，不发“停止”聊天消息，不等会话空闲、不要求用户到只读面板操作。它保留对话和文件；独立演化实验不会随会话停止自动取消，外部也不能直调实验控制接口，需在原会话空闲后 `append` 请云端取消或由用户在网页端处理，见恢复文档。只说“不用盯着”则停止本地查询即可。
工具超时按 `continuation.tool_timeout_seconds` 设置，文件上传另留时间。需要交还控制权时说明如何续查；没有实际通知能力不承诺主动提醒，但不在每轮重复“没有通知机制”等技术说明。

## 按需读取

- 首次提交、审批、修改需求或启动演化：读 [完整流程与命令](references/workflow.md)。
- 长任务、进度展示、持续跟进、宿主能力差异：读 [等待与交互](references/interaction.md)。
- 交付计划、报告、明细，或打开/刷新链接：读 [文件与面板交付](references/delivery.md)。
- 请求失败、命令中断、找回会话或停止任务：读 [恢复与异常](references/recovery.md)。

正常交付只展示具名的任务或文件链接，不附加有效期、一次性票据等登录技术说明；用户询问时再解释。链接失效时自行刷新，只提示“已刷新查看入口”。不预打开消耗用户链接。
工作空间/演化面板链接不展示对话详情；所有业务问题、决策与结果必须在当前宿主里可读，不让用户跳网页才能知道发生了什么。命令、会话号、等待参数和工具内部日志由你管理。普通求解不自动升级为深度演化。
