# 等待与交互

## 业务详情留在当前对话

当前宿主是用户的主界面。云端工作空间与演化面板隐藏对话，不具备完整会话查看或会话停止按钮，不能让用户跳过去才能理解任务。

| 时机 | 当前对话需要说明的内容 |
| --- | --- |
| 数据检查 | 输入规模、发现的缺失/冲突、对求解的影响；仅有工具活动提示时不编造检查结果 |
| 澄清 | 云端问题的原意、全部有实质区别的选项和取舍，已有答案不重复询问 |
| 方案审批 | 输入范围、加工/业务规则、目标顺序、求解与验收范围、预期交付；不只说“是否确认” |
| 求解进行中 | 已完成的具体业务工作、当前问题和接下来要做的事；不凭工具名声称阶段已完成 |
| 求解结果 | 结果指标、方案含义、核验结论、局限与每个文件入口；不能只给链接 |
| 演化 | 创建/初始化/迭代/实验结束分别描述，给实际结果变化和未完成工作；进度不自行换算轮数 |
| 错误/停止 | 对任务实际影响、已保留成果、远端是否确认停止；不要把内部协议原文堆给用户 |

读取 `status_markdown` / `workflow_steps`（全局流程与当前步骤）、`message`（最终答复）与 `messages`（本轮已公开的业务说明）；`recent_replies` 用于找回最近已结束轮次的公开答复，引用时明确它属于历史，不当成本轮新结果。`subtask_results` 是已结束子任务的报告，只摘取明确的业务结果与限制并标为阶段信息，不转发实现命令/路径，不等同主控最终验收或已交付文件。结合当前回合归纳，不转发模型内部思考或逐工具日志。
`update.changed=false` 时不重复同一状态；有阶段推进或新业务发现则先把 `status_markdown` 和简短中文进展发给用户，再按 `continuation` 续查。
“正在调用工具”只能说明活动，不等于数据检查完成、求解成功或验证通过。不能为了简短删掉关键假设、限制或未达标结论。

## 三种观察方式

**interactive（默认）**：完全由远程伐谋 Agent 状态决定流转，不设轮询次数或时间阈值强行中断。客户端内部按 60→120→180→240 秒自适应守候，一旦云端产生澄清、审批、报错或交付会立即返回。只要本轮仍在云端运行，就沿用 `continuation.argv` 持续跟进，直到云端需要用户决策、本轮完成交付或演化转入云端后台。
调用 `continuation.argv` 时，工具描述使用简短中文（可直接取 `continuation.tool_description`，如“等待伐谋执行求解与核验（第4/5步）”），避免一连串英文命令刷屏。

**follow**：用户明确要求“跟到演化结束”时，连同转入后台的深度演化也一并持续跟进，直到实验终态与最终报告交付。期间审批/澄清仍交给用户；不把旧回执当实时实验状态。

**peek**：用户明确只要当前状态、不等结果时观察一次，默认 15 秒；转达 `status_markdown`、已知详情和未知项后结束。原任务仍保留。

单次命令窗口不是完整任务期限。只有宿主本身真实触发轮数/时长保护时，才保存原会话、展示当前 `status_markdown` 与已有业务详情后交还控制权；这不是正常查询的默认终点。

## 宿主能力与页面入口

有后台进程句柄先收原进程输出；有中间消息就用业务语言更新，不并发另开同会话查询。无消息/唤醒能力不能承诺稍后自动通知。
不按WorkBuddy或DSH名字猜能力；不造宿主工具或按钮。Skills不能改变转圈动画，靠及时的中间反馈和真实阶段结果改善等待体验。
有可跨回合唤醒的后台能力才安排自动跟进；未验证前不承诺。已有用户“持续跟到结束”的明确要求时使用follow，其余按短时观察处理。

停止本地观察、停止会话当前回合、取消独立演化实验是不同动作。用户要求远程停止时走恢复文档的真实控制命令。
